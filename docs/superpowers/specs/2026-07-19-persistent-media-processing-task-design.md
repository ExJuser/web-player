# 媒体处理任务后台运行设计

## 目标

LADA 马赛克修复和精彩片段剪辑任务启动后，由项目后端独立执行。刷新或关闭页面不取消任务；只要项目后端进程仍在运行，任务就持续运行。页面重新打开后自动显示当前进度，任务已结束时显示完成或失败结果。

任务不跨后端进程重启恢复。后端停止时，正在运行的外部处理进程随之终止。

## 当前问题

前端通过一个持续的 NDJSON 请求接收进度，服务端监听响应连接的 `close` 事件并调用 `AbortController.abort()`。页面刷新或关闭会断开连接，因此实际处理任务也被取消。

## 方案

新增进程内媒体处理任务管理器，统一管理 LADA 和剪辑任务。任务管理器持有任务 ID、类型、影片名称、进度、状态、运行状态、结果、错误和 `AbortController`。HTTP 请求只负责创建、查询或取消任务，不再拥有任务生命周期。

继续限制同一时间只能运行一个媒体处理任务。活动任务完成、失败或被取消后释放执行槽；最近一个终态任务保留在内存中，供页面刷新后读取，直到新任务启动或后端重启。

## 接口与数据流

1. 前端向现有 LADA 或剪辑创建接口提交参数。
2. 后端校验当前没有活动任务，创建任务记录并立即返回任务摘要，然后异步执行实际处理。
3. 处理过程通过任务管理器更新进度和状态，不再向原始响应流写事件。
4. 前端每秒查询当前媒体处理任务；应用首次加载时也立即查询一次。
5. 查询到活动任务时，前端恢复顶部任务入口和进度弹窗状态。查询到终态任务时，前端停止轮询并显示现有完成结果或就近错误消息。
6. 用户点击取消时，前端携带任务 ID 调用取消接口；任务管理器仅取消匹配的活动任务。

接口采用以下职责：

- `POST /api/media/highlight-montage`：创建剪辑任务，返回任务摘要。
- `POST /api/media/lada/restore`：创建 LADA 任务，返回任务摘要。
- `GET /api/media/processing-task`：返回活动任务或最近一个终态任务；没有任务时返回 `null`。
- `DELETE /api/media/processing-task`：按任务 ID 取消活动任务。

## 前端状态

现有 `MediaProcessingTaskState` 增加后端任务 ID 和运行状态。两个创建控制器改为创建任务后接收任务摘要，不再持有决定后端任务存亡的请求 `AbortController`。

应用级轮询负责同步任务状态，并复用现有任务弹窗、顶部后台任务入口、完成结果弹窗和消息提示。关闭进度弹窗只改变 `isDialogOpen`，不会影响后端任务。显式取消才请求后端终止任务。

为避免终态结果在同一次页面会话中反复弹出，前端记录已处理的任务 ID；重新加载页面后仍可重新读取最近结果。

## 错误与边界

- 创建任务时已有活动任务：返回冲突错误，保留当前任务。
- 取消的任务 ID 与活动任务不匹配：返回明确错误，不误杀其他任务。
- 页面轮询暂时失败：保留最后一次已知状态，后续轮询自动重试。
- 任务失败或取消：记录终态和错误消息，清理临时文件，并释放媒体处理执行槽。
- 后端进程退出：不承诺任务恢复，也不把外部进程转移为系统级常驻服务。

## 验证

仅运行最小范围验证：

- 任务管理器单元测试：断开页面连接不取消、进度更新、显式取消、终态保留、并发任务拒绝。
- LADA 与剪辑相关接口测试：创建立即返回、查询状态、取消任务、完成和失败状态。
- TypeScript 静态检查或相关类型测试，确认前后端任务结构一致。

不默认运行全量测试、全量构建或浏览器检查。
