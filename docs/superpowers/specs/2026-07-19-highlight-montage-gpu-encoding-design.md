# 剪辑版 GPU 编码设计

## 目标

生成剪辑版时优先使用本机可用的 H.264 硬件编码器，降低 `libx264` 占满 CPU 导致的卡顿；硬件编码不可用时自动回退软件编码，保持现有功能可用。

## 方案选择

可选方案包括：固定使用某一种 GPU 编码器、只根据 FFmpeg 编码器列表选择、对候选编码器执行最小初始化探测后选择。采用第三种方案，因为它能同时覆盖 NVIDIA、Intel 和 AMD，并能识别“FFmpeg 包含编码器但显卡或驱动不可用”的情况。固定配置会增加用户设置成本，只检查编码器列表则可能在正式剪辑时失败。

## 设计

- 剪辑任务开始转码前，按 `h264_nvenc`、`h264_qsv`、`h264_amf` 的顺序执行短时、无输入文件的编码初始化探测。
- 使用首个探测成功的编码器生成现有 `trim`、`atrim` 和 `concat` 滤镜输出；音频仍使用 AAC。
- GPU 编码参数保持 H.264 与 `yuv420p` 输出兼容性，并为不同后端使用各自的质量参数。
- 所有候选均不可用时使用当前 `libx264 -preset fast -crf 20` 参数。
- 探测只影响剪辑任务，不改变播放器转封装、字幕提取或其他 FFmpeg 流程。

## 错误与回退

候选编码器探测失败属于预期能力检测，不向用户报错；全部失败时静默回退 CPU。正式剪辑仍沿用现有超时、取消、临时文件清理和任务错误提示。

## 测试

- 验证每种编码后端生成正确参数。
- 验证按优先级选择首个可用硬件编码器。
- 验证全部硬件编码器不可用时回退 `libx264`。
- 保留现有剪辑、进度、输出落盘和清理测试。
